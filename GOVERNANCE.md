# Governance

The repository is maintainer-led. Maintainers set release scope, review contributions, protect security and accounting safety, and may appoint additional maintainers based on sustained contributions.

Decisions favor portability, explicit configuration, stable external identifiers, idempotency, safe defaults, and transparent limitations. Breaking changes require an issue, migration notes, and a major version. Security fixes may be prepared privately. Releases require passing CI, a clean secret scan, updated changelog, and verified package metadata.
